# VIA Trust Labels

VIA must keep access state separate from trust state.

Allowed factual access wording includes `Guest`, `DeSo login required`, `DeSo authenticated` or similarly precise states once technically verified.

Do not derive `Verified`, `Trusted`, `Safe`, `Human`, `Scam-free` or equivalent labels merely from:

- owning a DeSo account;
- having a positive $DESO balance;
- buying $DESO;
- displaying a public key;
- passing a single anti-bot check;
- having an old account.

Any future blue-check or trust label needs a separately documented evidence source, revocation rule and user-facing meaning.
