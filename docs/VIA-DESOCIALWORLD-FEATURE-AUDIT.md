# VIA social feature intake

## Purpose
VIA may learn from useful public product patterns seen across DeSo applications, including DeSocialWorld, without copying proprietary code, branding or protected product names.

## Already present in VIA
The current VIA social surface already includes:
- posts up to 5000 characters;
- up to four images per post;
- DeSo-backed image upload;
- DeSo-backed video upload;
- replies;
- Like;
- Follow / Unfollow;
- Repost / Quote path;
- Diamonds;
- polls and poll voting paths;
- local saved posts;
- Following, Recent and Discovery views;
- public community and world/discovery pages.

These capabilities must be improved inside VIA rather than duplicated as separate subsystems.

## Generic candidates worth adding when DeSo support is verified
1. Edit-post support, but only through an official/current DeSo transaction path and the same prepare -> review -> approve -> submit boundary used for other writes.
2. Notification categories and filters for mentions, replies, reposts, follows, diamonds and other DeSo-backed events when reliable source data is available.
3. Language and region feed preferences when they can be derived from reliable public metadata or explicit user preference. A preference must never pretend to translate a post or infer a user's location in the background.
4. Better long-form/blog presentation using VIA's existing 5000-character post capability instead of creating a proprietary parallel publishing format.
5. Media-first feed options using VIA's existing multi-image and video support.

## Explicit exclusions
- Do not use the Post2Earn name, hashtag, branding, trademark, slogans or branded reward mechanic.
- Do not copy or scrape proprietary source code, private APIs or protected visual assets from another application.
- Do not present another application's feature or brand as a VIA feature.
- Do not add a paid per-post translation provider by default.
- Do not add a recurring external service cost merely to imitate another application's convenience feature.

## Translation boundary
DeSo posts remain in their original language. VIA may keep its interface multilingual and may later add an optional translation action only if a reliable free or near-zero-cost method is available and privacy/cost boundaries are clear. Until then, no automatic translation call is made.

## Product rule
Useful generic ideas may be adopted only when they improve VIA, fit DeSo's documented/current capabilities, remain affordable, and pass VIA's existing security and consent boundaries. Inspiration is acceptable; proprietary replication is not.
