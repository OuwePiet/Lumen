# VIA language and translation principle

## Purpose
VIA is an international meeting place. The interface should therefore be able to support multiple languages without turning translation into a recurring cost centre for VIA or its users.

## Interface language
- VIA may provide its own translated interface strings for supported languages.
- A visitor chooses the VIA interface language intentionally.
- The chosen interface language applies consistently across VIA's separate pages.
- The language architecture must remain extendable; adding languages later should not require rebuilding navigation or page structure.
- Right-to-left languages such as Arabic must be considered in the interface architecture before they are activated.

## DeSo posts remain original
- A DeSo post remains in the language in which its author published it.
- Changing the VIA interface language must not alter, overwrite or silently translate post content.
- VIA does not automatically send public posts to an external translation provider.
- VIA does not provide a paid per-post translation API by default.

## Translation by the user
When a visitor wants a translation, the simple default is to copy the text and use a translator of their own choice outside VIA. VIA does not need to forward the post, choose a provider for the visitor or pay an API charge.

This keeps control with the visitor and avoids unnecessary provider dependency, privacy exposure and recurring translation costs.

## Cost principle
VIA's general principle is to keep creator and visitor costs modest and transparent. A paid external service should not be added merely for convenience when the same optional task can reasonably be performed by the user without VIA incurring a recurring charge.

This does not mean every external service is rejected. Where an external service is necessary for a core VIA function, its purpose, cost and alternatives must first be assessed and any user-attributable cost must be clear before commitment.

## Personal user guide
The personal VIA user guide/onboarding must explain in ordinary language:
- VIA aims to remain simple, affordable and sustainable;
- the VIA interface can be offered in supported languages;
- user posts remain in their original DeSo language;
- VIA deliberately does not pay to translate every post;
- a user who wants a translation can copy the text and use a translator of their own choice;
- this is an example of VIA avoiding unnecessary recurring costs rather than passing them on to creators or visitors.

## Boundary
This document defines product behaviour and cost policy. It does not enable login, wallet access, signing, blockchain writes, external translation calls, background geolocation or paid provider use.
