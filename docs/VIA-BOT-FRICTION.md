# VIA Bot Friction

VIA should not rely on one CAPTCHA, one payment or one login as its complete bot defence.

The intended layers are:

1. Guests cannot write public/community state.
2. Participation requires verified DeSo authority.
3. DeSo's own current balance/funding restrictions can make mass account creation less attractive, without VIA treating payment as trust.
4. VIA write surfaces add reasonable rate limits, cooldowns and burst/duplicate protection.
5. Link, media and impersonation abuse have their own checks.
6. Repeated abuse can be restricted on VIA-controlled surfaces.
7. Financial/blockchain actions always retain their stronger transaction controls.

The purpose is to make automated abuse expensive and containable while keeping ordinary public browsing easy.
